# 开发流程规则

1. **每次写完代码后必须进行完整测试**：包括模块导入测试、API 端点测试、端到端功能测试。
2. **测试通过后用中文写更改说明并提交到 GitHub**：commit message 必须使用中文，清晰描述本次更改内容，以便追溯和回退。
3. **提交粒度**：每个功能或修复作为一次独立提交，避免将不相关的变更混在一起。
4. **每次修改代码后必须主动询问是否增加小版本号**：
   - 每次代码编写与测试验证完成后，必须主动向用户询问：“本次修改是否需要递增小版本号（例如从 X.Y.Z 升级到 X.Y.Z+1）？”；
   - **若用户确认递增**：更新 `package.json` 中的 `version`，同步更新 `package-lock.json`，在 `CHANGELOG.md` 顶部生成版本发布记录与变更摘要，并执行 `npm run version:gen` 更新前端打包元数据；
   - **若用户否定或未确认**：继续沿用当前版本号，不修改版本配置；
   - 确保今后在打包分发时不会重复使用同一个旧版本号。
